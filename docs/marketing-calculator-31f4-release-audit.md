# #31F4 — выпускная приёмка экономики V1/V2

**Статус**: кандидат релиза. F4 не считается закрытым до проверок на exact PR SHA, слияния и побайтовой проверки опубликованного GitHub Pages. Материнская задача #31 остаётся OPEN до формального финального решения.

## Граница продукта

Только существующий \`Marketing_calc.HTML\`, связанный портфель V2, прогноз/цена/прибыль/Cash Flow. Не касаться заказа, оплаты и любых действий после оплаты. Не переписывать V1 и не менять исходные утверждённые финансовые значения.

## Независимые и регрессионные доказательства

1. Сохранить проверяемый однотоварный расчёт V1, включая неизменность диапазона цены и графика кредита; source-contract цена онлайн-услуг не меняется.
2. Проверить строго 5 источников в одном расчёте: own, resale, dropship, offline salon, online agent; 3 типа связей, 3 общих ресурса, 3 месяца продаж, 5 месяцев денежных событий.
3. Для каждого SKU/месяца сверять объём, цену, скидки, выручку без НДС, COGS реально реализованных единиц, расходы на маркетинг/ресурсы, зарплату/аренду, проценты, налоги и after-tax P&L.
4. Сверять складские остатки и отдельно оценивать непроданный запас. Фактический платёж за всю партию — cash, COGS — по мере реализации.
5. Независимо восстановить денежные поступления, комиссии, реальные расходы на закупки и исполнение, проценты и тело кредита, тайминг налогов; owner capital — по ежедневному максимуму кассового разрыва. Сумма SKU должна сходиться с портфелем без balancing plugs.
6. Тестировать положительные и отрицательные сценарии: налог на прибыль обычного бизнеса плюс агент; запрет совместного неатрибутированного онлайн-ресурса; дефицит мощности; превышение V1 priceMax; неполный источник периода; уменьшение запасов.
7. Проверить VAT=20 как **выручку/операционный Cash Flow без транзитного НДС**, не называть банковским остатком с НДС.
8. Устранить найденное в F4 ложное подтверждение цели: если разовый расход/актив не имеет подтверждённой амортизации, финансовые значения **предварительные**. Никаких \`TARGET_MET\` / \`targetMet=true\` на уровне полного бухгалтерского периода. Денежный платёж и числовая оценка остаются доступны; предупреждение видно и сохраняется после Back/Resume.
9. Chromium на 390 px: смешанный пяти-SKU сценарий, работа с ресурсами, смена мощности, явная ошибка/восстановление, ценовые пределы, возврат к заполненным полям.
10. Весь старый набор тестов запускается без ослабления; GitHub Actions на **том же exact PR SHA** GREEN. После слияния тест на \`main\` сверяет SHA256 опубликованного GitHub Pages HTML и десяти JS-модулей с файлом из checkout; без «сайт открылся, значит новая версия».

## Граница неподдерживаемых контрактов

- Общий регулярный ресурс между отдельными налоговыми владельцами при \`profit\` без атрибуции собственника: **HOLD**, а не искусственный налог.
- Платная реклама без проверенного владельческого CAC или плательщик не подтверждён: **HOLD**.
- Не сходится фиксированная точка при revenue-weighted attribution и зависимости от скидок: **HOLD**.
- Разовый актив без графика признания затрат: **PROVISIONAL**, цель полного периода не подтверждена.
- \`vatCashBasis='net-of-vat-operating'\`: **не** полный VAT-inclusive банковский счёт. Не декларировать существование gross VAT charge/remittance.
- Запасы, срок воронки онлайн-V1, доступность услуги, договорные сроки выплат и кредита остаются строгими источниками истины.

## Условия окончательного gate

**GREEN** только при одновременном наличии:
- точного SHA PR с зелёными обязательными калькуляторными и Chromium workflow;
- независимых исходных чисел и полного списка PASS/FAIL, включая новый предварительный статус;
- main squash SHA и подтверждённой публикации;
- строгого SHA256 соответствия всех 11 опубликованных критичных артефактов;
- карты #31 с честным указанием поддерживаемого периметра и всех HOLD.

При неуспехе хотя бы одного пункта: **F4 OPEN**, #31 OPEN. Отсутствие внешнего доступа и непроверенная публикация **не** считаются GREEN.
