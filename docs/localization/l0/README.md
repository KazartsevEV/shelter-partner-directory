# L0 · машинный реестр текстовых поверхностей

База: принятый PR #134, merge `9e5a7f51`. Код приложения и финансовые формулы не меняются. Это первый подэтап задачи 4, а не приёмка полной локализации.

## Реестр

- [summary.json](summary.json): объём, категории, ограничения и внешние ресурсы.
- [catalog.json](catalog.json): SHA256/владельцы всех 29 источников, строки общего словаря и независимых словарей модулей, 74 переменных шаблона, ссылки на страницы записей.
- [entries/](entries/): все исходные вхождения по модулю, до 400 записей на страницу; файл, строка, смещение, функция/HTML-контекст, владелец, рекомендуемый L1–L5, текст, атрибут, параметры шаблона и структурный статус покрытия.
- [candidates.json](candidates.json): консервативная очередь на разбор. Это **не число доказанных отсутствующих переводов**. Содержит шаблоны и не сопоставленные напрямую литералы, включая части HTML и отдельные числовые/единичные подписи.
- Browser census: самостоятельный артефакт CI с фактически отображёнными строками/атрибутами, контекстами, языком, шириной, пропусками старой диагностики и переполнениями. Он дополняет исходный реестр, который также охватывает скрытый и условный код.

Исходный обход: HTML parser + JavaScript AST. Скрипты приложения при извлечении не исполняются; скрытые ветки не зависят от возможности открыть их кликом. Захватываются text nodes, metadata, placeholder/title/aria/alt/label, CSS `content`, строковые литералы, встраиваемая разметка, template literals с исходными выражениями, regex и словари RU/EN/KK. Все локальные JS/CSS entrypoint охвачены, включая финансовые модули, генерирующие ошибки для UI.

## Как читать статус покрытия

| Категория | Значение |
| --- | --- |
| `catalog-entry` | Вхождение внутри существующего трёхъязычного словаря или переменного шаблона; наличие не доказывает профессиональную точность перевода |
| `legacy-exact` | Нормализованный литерал точно совпал с ключом общего словаря; не гарантия достижимости конкретного DOM узла |
| `protected-or-component-owned` | HTML помечен защитой от общего переводчика; проверить владельца отдельного компонента или пользовательских данных |
| `unmapped-candidate` | Прямого ключа нет; это может быть истинный пробел, составная строка, отдельная единица, metadata или строка собственного renderer |
| `dynamic-review` | Динамическое выражение/русскоязычный regex; нужны проверки захватов, чисел, имён, направления перевода и ветвей ошибок |
| `technical-or-latin-review` | Сохраняется для полноты: машинные ID/enum/селекторы/URL, латинские строки. Не переводить автоматически; латинский текст также может оказаться UI |

Смещение обычного AST-литерала измеряется в UTF-16 code units и относится к исходнику. Для разобранной встраиваемой разметки это привязка к родительскому литералу плюс позиция декодированного фрагмента; при escape-последовательностях точную строку/колонку следует сверять по родительскому `js-string`/`js-template`. `legacy:<hash>` — только ID инвентаризации. Миграция на семантические ключи выполняется в L1 с совместимостью прежних источников.

## Воспроизведение

```sh
npm ci --prefix scripts/localization --ignore-scripts --no-audit --no-fund
node scripts/localization/inventory.cjs
node scripts/localization/inventory.cjs --check
node tests/nomad360_localization_inventory.test.cjs
```

Acorn 8.15.0 и parse5 7.3.0 зафиксированы lockfile; используются только при разработке и CI. `--check` сравнивает все страницы и отбрасывает устаревшие/лишние записи. Добавление строки или локального script/link требует регенерации. Материалы не подключаются в HTML и не попадают в пользовательскую выгрузку.

## Подтверждённые находки для следующего подэтапа

На неизменённом `nomad360_locale_core.js` строки **«Чек 1: нужен непустой список items.»** и **«Чек R1: неверная позиция 2.»** остаются русскими при `translate(...,'en')` и `translate(...,'kk')`. Два соответствующих regex содержат двойное экранирование `\\d`/`\\.` (строки 1372–1373). Результат воспроизведён, а не выведен только из наличия шаблона. Это реальный пробел пути ошибки; исправляется и проверяется на следующем подэтапе, L0 его не маскирует.

В итогах самостоятельного V2 остаётся русский фрагмент **«. Денежные доли суммарно 100%.»** (`portfolio_v2_ui.js`, строка 272); составная подпись не имеет прямого ключа общего переводчика. Старый `auditVisibleGaps` также может пометить корректную казахскую строку, поскольку проверяет общий кириллический диапазон. Browser census сохраняет исходный сигнал, отдельно отмечая точные совпадения с KK-словарём; их нельзя считать доказанными русскими утечками.

Отдельно требуют проверки EN `partner` и KK «серіктес» в переменной диагностике V1 при действующем русском «принципал». Термины Margin/Markup, Available Cash/Free Cash Flow, LTV Factor и прочие группы из карты проверяются по формуле и профессиональным источникам в L1. Здесь их правильность не утверждается.

## Границы

`index.html` — партнёрский каталог, вне области калькулятора. ExcelJS — сторонняя библиотека без интерфейсного словаря; её код исключён, собственный экспортёр включён. Tailwind, виджет внешнего провайдера и его iframe не являются управляемыми проектом переводами. Полная лицензия и маркетинговые документы относятся к отдельной задаче 6; действующие HTML/footer строки входят в реестр. Уровень L0 не означает принятие языка, завершение L1–L6 или объявление EN каноном.
