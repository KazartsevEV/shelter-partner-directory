# TYPE-02 — системная типографика Nomad360 lite

**Статус:** новая самостоятельная CSS-задача для Codex, **строго между задачами 5 и 6**. Не начинать до приёмки задачи 5. Один PR, отдельный визуальный эталон, затем масштабирование и ручная приёмка.
**Карта работ:** docs/nomad360-codex-task-map.md. **Следующая маркетинговая задача:** docs/nomad360-marketing-localization-tz.md.
**Источники:** опубликованная страница Nomad360 lite и пользовательские скриншоты от 12–13 октября 2026 года: главный экран, валюта/черновик, карточка сертификата V2, результат портфеля, О проекте/Контакты.

## 1. Цель и диагноз

Привести весь калькулятор к единой спокойной профессиональной типографике: ясная последовательность **раздел → заголовок карточки → вопрос/метка → поле → пояснение → результат**. Убрать эффект, когда заголовки, инструкции, метки полей и ошибки постоянно конкурируют за внимание.

Исследованные причины в действующем коде:
- nomad360_design_system.css: стандартные роли имеют веса body 500, label 600, note 500, section 700, action 700, а body 17px, label 16px, note 15px, action 18px.
- Глобальное правило body > section :is(.text-xs,.text-sm) принудительно превращает обе утилиты в 15–16px через important; отдельные правила жирнят .font-semibold и заголовки. Это разрушает разделение основного и вторичного текста, особенно в динамической V2.
- Marketing_calc.HTML и nomad360_calculator_ui.css используют font-weight 800/900 и дробные 650/850, хотя Google Fonts IBM Plex Sans импортируется лишь с начертаниями 400/500/600/700. В браузере возможна синтетическая жирность.
- Блок О проекте отображает основной текст на 14px и вложенные заголовки на 15px, хотя рядом располагаются значительно более крупные заголовки и свободное пространство.
- В формах V2 длинные белые подсказки на синем и подписи внутри белых карточек чрезмерно тяжёлые; красные проверки должны оставаться заметными, но не заменять общий визуальный ритм.
- В CSS много поздних переопределений; нельзя лечить систему очередным слоем глобальных important в конце файла.

**Сохранить:** текущий крупный, выразительный первый экран и его композицию; синий, белый, оранжевые CTA; формы и математический смысл.

## 2. Гарнитура и языки

Предпочтительный кандидат единой интерфейсной гарнитуры — **Inter** 400/500/600/700 с единым font-stack. Однако переход делать **только после A/B сравнения** Inter против **IBM Plex Sans с исправленными весами**. На первом эталонном экране сделать оба варианта; выбрать более чистый по реальным RU/EN/KK скриншотам. Если Inter проигрывает или не обеспечивает все казахские глифы, оставить IBM Plex Sans и полностью исправить типографическую систему. Не смешивать две гарнитуры внутри одной формы. Фирменное написание логотипа в хедере можно сохранить без изменений, если требуется.

Проверить реальное отображение и отсутствие fallback-разрывов в казахском тексте: **Ә ә Ғ ғ Қ қ Ң ң Ө ө Ұ ұ Ү ү Һ һ І і**. Тестировать кириллицу, латиницу, числа, валюты, проценты.

Подключать выбранную гарнитуру централизованно, не дублировать @import. Загрузить только используемые начертания; использовать font-display:swap и системный fallback. Для скачиваемого HTML и при недоступных Google Fonts интерфейс сохраняет читаемость и сетку. Не обещать отсутствие сетевых обращений к поставщику шрифтов.

## 3. Шкала ролей CSS (начальные параметры для сравнения)

| Роль | Размер | Вес | line-height |
| --- | --- | --- | --- |
| Главный hero-вопрос | сохранить текущую адаптивную крупную шкалу ~34–55px | 700 | 1.1–1.18 |
| H2 раздела V1/V2 | 23–26px | 600 | 1.22–1.30 |
| H3 карточки | 18–20px | 600 | 1.30–1.38 |
| Обычный текст | 16–17px | 400 | 1.5–1.6 |
| Метка поля | 15–16px | 500 | 1.38–1.45 |
| Введённое значение / select | 16px | 400–500 | 1.4–1.5 |
| Placeholder | 16px | 400 | 1.4–1.5 |
| Подсказка, пояснение | 14–15px | 400 | 1.48–1.55 |
| Кнопки | 16–17px | 600 | 1.3–1.4 |
| Ошибка/валидация | 14–15px | 500 | 1.4–1.5 |
| Денежный KPI | 20–28px | 600–700 | 1.2–1.35 |
| Таблицы | 14–16px | 400–600 по роли | 1.4–1.5 |
| О проекте / Контакты | body 15–16px, H2 21–22px, H3 16–17px | body 400, heading 600 | 1.5–1.65 |
| Футер/реквизиты | body 14–16px | 400–600 по роли | 1.45–1.55 |

Эти значения — ориентиры, а не требование сделать все формы одинаковыми. Сохранять минимум **16px в текстовых input/select на телефонах** против автозума iOS. Не опускать смысловые пояснения пользовательской формы до микротекста 11–12px.

Сохранить смысловые классы nd-type-body, nd-type-section, nd-type-label, nd-type-note, nd-type-action, nd-type-number и привести их к одной роли. Ввести единый источник токенов для размеров, насыщенности и межстрочных интервалов. Старые переменные nd-type- можно оставить временными алиасами. Не создавать конкурирующие CSS-источники.

**Устранить источник ошибки каскада:** убрать/сузить глобальные селекторы для всех .text-sm, .text-xs, .font-semibold, h2/h3/h4; использовать семантические и контекстные селекторы. Порядок приоритетов должен быть объясним, без десятков новых important. Из-за Tailwind CDN обязательно проверить и DOM после динамической перерисовки V2.

## 4. Эталонные экраны и порядок работы

**Этап A — один экран, только визуальный эталон.**
- Самостоятельный V2, секция «3. Закупка и сертификаты»: синий заголовок, обычное длинное описание под ним, белая карточка «Сертификат / лицензия», метки, select, input, подписи чекбоксов и вторичные подсказки.
- Предъявить RU/EN/KK в **двух шрифтовых вариантах**, с до/после и computed styles для названных ролей. Пока не трогать остальные сценарии и не объединять PR. Продолжить только после визуальной приёмки эталона.

**Этап B — внедрение согласованных ролей.**
- V2: «Результат портфеля», CAC и сводки, источник капитала, кредитное пояснение и валидация. Красный текст ошибки заметен, но не перетягивает внимание всех меток.
- Главная: сохранить текущую крупную выразительную композицию вопроса и сетку шести результатов; менять только системную согласованность, не редактировать продуктовые тексты (задача 6).
- Валюта и блок восстановления черновика: читаемые H2, метка селектора, обычный текст, действие.
- «О проекте», «Контакты»: повысить читабельность мелкого основного текста, убрать бессистемную жирность, выдержать спокойные H2/H3.
- Остальные V1/V2: товары, онлайн-/офлайн-услуги, агент, упрощённый/полный расчёт, связанный V2, прайс, калькулятор кредита, денежные показатели, справочные и отчётные блоки. Распространять принятые роли, избегая специфических исключений без необходимости.
- Печатные/PDF-блоки: не нарушать существующий размер листов и числовые итоги; если текущая PDF-типографика самостоятельная и стабильна, не заменять её ради единства экранной гарнитуры.

## 5. Читаемость и визуальный ритм

- Использовать повторяемые вертикальные расстояния 4/8/12/16/24px там, где уместно; обеспечить separation between heading, description, field and help, без новых декоративных плашек.
- Длинные финансовые пояснения ограничивать по удобной длине строки, где позволяет сетка (ориентир 65–85 символов); **никогда не обрезать** предупреждения через ellipsis или max-lines.
- Проверить контраст WCAG AA: обычный текст ≥4.5:1, крупный ≥3:1. Палитра Nomad360 сохраняется. Никаких новых зелёных/фиолетовых блоков.
- Сохранить условия и момент появления ошибок, aria-live, счётчики, красную границу поля и локальные подсказки. Только typography/spacing; **не скрывать ошибки ради чистоты**.
- Все кнопки/селекты/чекбоксы доступные, активные зоны ≥44px, работа focus не нарушена. Особенности локализованной даты — задача локализации, не TYPE-02.
- Для финансовых чисел tabular nums, точные ISO-коды, читабельные минусы и проценты, отсутствие обрезания и неверного смешения шрифтов.

## 6. Разрешённые файлы и запреты

Основные: **nomad360_design_system.css**, **nomad360_calculator_ui.css**, встроенный CSS **Marketing_calc.HTML**. В JS-модулях, генерирующих динамическую форму, допустимо **только добавление семантических CSS-классов**, если CSS-селекторами добиться результата нельзя; нельзя изменять data-атрибуты, ID, формулы, пользовательский текст, условия валидации, роутинг и внутренние значения.

**Не изменять:** V1/V2 финдвижки, валюты, налоги, VAT, кредиты, Cash Flow, расчётную логику, черновики, финансовые данные пользователей, лицензию, реквизиты поддержки, работу экспортов. Не объединять в один PR маркетинговую упаковку, SEO или редактуру контента.

## 7. Definition of Done

- Объяснена реальная первопричина жирности с CSS-селекторами и computed style before/after, а не только субъективное «стало легче».
- Принятый A/B один экран V2; затем сделан полный проход всех форм и информационных блоков без нарушений hero.
- EN/RU/KK, тест реальных казахских глифов; нет чужеродных вставок fallback.
- Скриншоты до/после: **320 / 390 / 768 / 1280px**, минимум 5 экранов: hero, валюта+черновик, сертификаты, результат портфеля, About/Contacts.
- Нет текстового overflow, обрезания, горизонтальной прокрутки страницы при 320/390px, видимость при браузерном zoom 200%.
- Все числовые результаты V1/V2, валидация, сохранения/восстановления, валюты и отчёты работают как прежде. Проверить печать и скачанный HTML с отключёнными внешними шрифтами.
- Unit, Chromium E2E и CI зелёные. Отдельный review в docs/reviews с описанием селекторов и скриншотами.
- **GREEN не равен приёмке. После работы остановиться; merge только по прямому разрешению.**
