# Nomad360 — пошаговая карта до первого релиза

**Срез фактов:** 28.10.2026. **Решение по полному Release 1:** **NO-GO**. Это оперативный маршрут от текущей разработки к выпуску, а не разрешение на merge, платные услуги, Google-операции или смену DNS.

**Источники истины:** [основная карта](nomad360-codex-task-map.md), [R1–R6](nomad360-production-readiness-plan.md), приватный [release gate #547](https://github.com/KazartsevEV/lazysellerV2/issues/547), [интеграционный Draft PR #544](https://github.com/KazartsevEV/lazysellerV2/pull/544), [аудит GCP Draft PR #522](https://github.com/KazartsevEV/lazysellerV2/pull/522) и `nomad360/launch/docs/release1-cloudrun-drive-sqlite.md` в приватном репозитории. В случае расхождения фактические результаты точной ревизии CI и live-проверок важнее исторических описаний.

## Что уже есть — не начинать повторно

- **Финансовое ядро, интерфейс, EN/RU/KK, Help, SEO, локальное сохранение/экспорт**: принятая публичная реализация. Текущий GitHub Pages не переключён на новый домен; 18 URL действующего sitemap ранее прошли HTTP 200. Перенос черновиков по явному JSON-импорту добавлен в #283; legacy-финансовые формулы не менять.
- **Партнёрская форма и тексты, будущий screenshot UX, native AES-256 ZIP, SQLite/журнал, локальные резервные копии, изолированный backend и контейнерный каркас**: существенная часть исходников подготовлена, но реальные бизнес-операции не включены.
- **Приватный интеграционный #544**: точный HEAD `01f848be8f8153b471fdd561bdd7b99c268bb7fa`, [CI 40578562848](https://github.com/KazartsevEV/lazysellerV2/actions/runs/40578562848) GREEN (22 ACL/preflight, 170 regular, 22 exclusive, 90 financial, native/offline/tenant — без отказов). Это **синтетическая** интеграционная приёмка, а не работающая облачная выдача. PR остаётся Draft и не слит в `main`.
- **Частичный реальный Google Drive-примитив**: владелец ранее подтвердил один технический объект с `200/409/409`, readback и cleanup; это **не доказывает** глобальную сериализуемость SQLite/outbox и защиту нескольких ревизий.
- **Текущий private runtime закрыт по умолчанию**: `businessReady=false`, `sideEffectsAllowed=false`; register/confirm/resend/status/placement/bugs дают HTTP 503. Не называть продукт с серверной выдачей готовым.

Владельцем подтверждено отсутствие repository secrets; через GitHub невозможно восстановить их ранее удалённые значения или узнать полный ID существующего облачного провайдера. Для подтверждения ID нужен ранее сохранённый owner-controlled GCP inventory/запись, не новый WIF и не сервисный ключ. Успех WIF proof всё ещё не доказывает доступ к owner Drive, Sheets, Cloud Run или биллинг.

## Ближайшая работа через GitHub / PowerShell без Codex

1. Установлено владельцем: `gh auth` работает; `AI_MARKETER_GCP_WORKLOAD_IDENTITY_PROVIDER` и `AI_MARKETER_GCP_SERVICE_ACCOUNT` **отсутствуют в repository Actions secrets**; GitHub Environments = NONE; одноимённые repo variables отсутствуют. Проверить организационную область, если она действительно используется, и источники существующей cloud identity. **Не генерировать новый WIF/SA вместо восстановления старого.**
2. GitHub Actions `nomad360-site-release.yml` уже связывает названия секретов с `nomad360-auth-preflight.yml`; последняя доверенная попытка [40236324539/attempts/3](https://github.com/KazartsevEV/lazysellerV2/actions/runs/40236324539/attempts/3) падает именно потому, что у `google-github-actions/auth@v2` пустой WIF provider. **Бесполезно повторять её без изменения привязки.**
3. `LazySeller-Windows-CI` по фактической диагностике владельца работает под той же Windows-учётной записью владельца, что и интерактивный PowerShell; `gcloud` установлен, но Google auth там 0. **Не выполнять owner `gcloud auth login` в этом профиле ради починки CI.** Дополнительный Windows-пользователь и Cloud Shell **не обязательные требования релиза**; нужен лишь доверенный, защищённый канал получения/подключения уже существующей identity. Остальной код и документацию продолжаем через GitHub без облачной авторизации.
4. После подтверждения корректной существующей WIF-identity — один read-only доверенный auth-preflight и затем безопасный GCP inventory; его результаты определят дальнейшие работы, не меняя уже действующий Infourok/Product Factory.

## Возможный отдельный более ранний выпуск — только статический калькулятор

**Не путать с полным Release 1.** Предварительный запуск автономного EN/RU/KK калькулятора без регистрации партнёров, индивидуальной доставки/писем и серверных обещаний можно рассматривать отдельным решением. Для него потребуются точный public build, регрессия финансовых/экспортных/locale сценариев, публичная QA/SEO/TLS, перенос черновиков и явная проверка, что выключенные серверные функции не обещаются пользователям. Наличие текущего GitHub Pages не означает, что новый домен или полная партнёрская версия уже запущены.

## Управление изменениями

- Каждый инженерный срез — отдельный PR, точный source/CI receipt, review, явная приёмка. Документационный PR **не разрешает** слияние #544, выкладку Cloud Run, Google provider writes, публичный cutover или новые расходы.
- Фиксировать состояния как `DONE_BY_SOURCE`, `CI_GREEN_SYNTHETIC`, `LIVE_PROVEN`, `BLOCKED`, `GO`; не превращать `GREEN` в `LIVE_PROVEN`.
- Исторические заметки основной карты от 26 октября сохраняются для аудита; этот документ — актуальный пошаговый release-frontier от 28 октября.
