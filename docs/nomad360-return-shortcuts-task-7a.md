# RET-07A — Возврат пользователей в Nomad360 lite: ярлыки Windows, iOS, Android

**Задача 7А — самостоятельная задача между SEO-07 (№7) и задачей №8.**
**Статус:** ТЗ, реализации нет. Отдельная ветка и Draft PR **после приёмки SEO-07**, до задачи 8. GitHub Pages остаётся текущим хостингом.
**Исходное приложение:** https://kazartsevev.github.io/shelter-partner-directory/Marketing_calc.HTML
**Связанные ТЗ:** [SEO-07](nomad360-seo-technical-spec.md), [маркетинговое ТЗ задачи 6](nomad360-marketing-localization-tz.md), [карта задач](nomad360-codex-task-map.md).

## 1. Задача продукта

Предоставить посетителю способ **возвращаться прямо к действующему Nomad360 lite** с рабочего стола Windows или главного экрана мобильного устройства. Цель — повторное использование калькулятора для новых бизнес-идей. Никаких новых аккаунтов, уведомлений, CRM, регистрации или сервера не требуется.

**Платформенные условия:** установить сайт/ярлык без согласия пользователя нельзя. На iOS браузеры не предоставляют стандартный JavaScript API для автоматического добавления на экран «Домой». На Android нативный запрос установки доступен только при поддержке браузера и выполнении условий PWA. На Windows скачивание обычного веб-ярлыка реально; перемещение файла на рабочий стол делает пользователь. Не выдавать показ справки или скачивание файла за успешную установку.

**Не называть ярлык нативным мобильным приложением:** прямо под действиями отображать заказанную фразу об отсутствии мобильного приложения. Веб-приложение/ярлык — способ быстрого доступа к сайту, а не приложение из App Store/Google Play.

## 2. Точная композиция интерфейса

**Один общий блок**, а не отдельные баннеры для V1 и V2; виден внизу калькулятора после расчётного интерфейса, **до раздела «Поддержать проект»**. Пользовательский последовательный порядок на мобильном и десктопе:

1. Дружелюбный баннер: изображение **отдельно подготовит и утвердит владелец**, без генерации или выбора стоковой картинки в рамках задачи. До утверждения — чистый компактный текстовый блок; не показывать сломанный или фиктивный image placeholder.
2. Крупная надпись **дословно RU**: **«Возвращайтесь к нам с новыми идеями!»**
3. **Ровно три пользовательских действия в этом порядке**:
   - **«Скачать ярлык на рабочий стол для Windows»**
   - **«Скачать ярлык для iOS»**
   - **«Скачать ярлык для Android»**
4. **Крупно, двумя отдельными строками RU, дословно**:
   - **«У Nomad360 пока нет мобильного приложения.»**
   - **«Мы растем на ваши деньги.»**
5. Ниже **существующий раздел «Поддержать проект»** с уже опубликованными реквизитами, криптовиджетом, Kaspi, международным банковским переводом и российским вариантом; ссылки и платёжные действия **не изменять**.

Верстка: фирменная палитра, читабельный синий текст и оранжевые основные действия согласно существующему дизайну; на desktop три кнопки в ряд при достаточной ширине, на mobile — колонкой по полной доступной ширине. Не превращать блок в рекламу, не добавлять платёжный CTA в баннер, кроме перехода к уже существующему разделу поддержки. Видимость не зависит от окончания конкретного сценария V1/V2, заполнения полей, подтверждения расчёта или локального сохранения; блок не дублируется внутри каждого результата.

**Точное расположение в реальном DOM:** текущий `nomad360_header.js` формирует `footerMarkup`, и первым служебным разделом footer сейчас является `<section id="nomad360-support">`. Вставить единый блок с уникальным ID (например, `nomad360-return`) **непосредственно перед этим support-разделом**; обеспечить описанный визуальный порядок в общем нижнем блоке интерфейса. При необходимости проверить фактическое расположение относительно `nomad360-information` и всех веток калькулятора: не переносить и не удалять существующие «О проекте», контакты, B2B, лицензию и подвал ради нового блока. После прохода по результатам на desktop/mobile путь к баннеру должен быть очевидным. Если без перестановки существующих разделов невозможно исполнить порядок «баннер → поддержка» именно сразу после расчётной области, зафиксировать минимальную корректировку DOM **без изменения содержимого старых секций** в PR.

**Изображение:** согласование отдельным шагом, изображения и визуальные макеты не придумывать. Существующий логотип разрешено переиспользовать для PWA-иконок только если он имеется и подходит требованиям, иначе вынести подготовку иконок на отдельную приёмку вместе с баннером. Не препятствовать текстовому и справочному сценарию, если картинка пока не утверждена.

## 3. Локализация RU / EN / KK

Использовать действующий `Nomad360LocaleCore` или словарь `nomad360_header.js` и событие `nomad360:languagechange`, чтобы при переключении языка **без перезагрузки** обновлялись заголовок, названия трёх действий, две крупные строки, все подсказки, заголовок и шаги справки, статусы, ошибки и доступные aria-label.

**Утверждённый оригинал RU — не переписывать, даже ради рекламной стилистики.**

**EN — предложенный смысловой перевод:**
- «Come back to us with new ideas!»
- «Download a desktop shortcut for Windows»
- «Get a home screen shortcut for iOS»
- «Get a home screen shortcut for Android»
- «Nomad360 doesn't have a mobile app yet.»
- «We grow thanks to your financial support.»

**KK — редакционный перевод, нуждается в локализационной проверке:**
- «Жаңа идеяларыңызбен қайта оралыңыз!»
- «Windows жұмыс үстеліне төте жолды жүктеп алу»
- «iOS басты экранына төте жол қосу»
- «Android басты экранына төте жол қосу»
- «Nomad360-ның әзірге мобильді қосымшасы жоқ.»
- «Біз сіздердің қаржылай қолдауларыңыздың арқасында дамып келеміз.»

Три кнопки на RU сохраняют **заказанные названия**. Под кнопкой/в открытой справке корректно пояснять различие возможностей ОС: Android/iOS не получают исполняемый «пакет ярлыка» с веб-страницы; вместо ложной «загрузки» показывается установка браузером или инструкция. EN/KK допускается естественная надпись «добавить», поскольку буквальный перевод «скачать» технически вводит в заблуждение. Не отображать пользователю статус «ярлык скачан» или «установлен», если это не подтверждено событием или браузером.

## 4. Windows: скачиваемый веб-ярлык

**Действие:** «Скачать ярлык на рабочий стол для Windows».

- Создать безопасный обычный файл `Nomad360-lite.url` (тип Internet Shortcut, **не .lnk и не .exe**) с целевым HTTPS-адресом действующего калькулятора под GitHub Pages. Внутри только известный формат Windows Internet Shortcut и URL, без скриптов, запуска команд, логина и неизвестных параметров. Не добавлять случайные теги отслеживания в URL.
- По клику браузер начинает загрузку файла (если не заблокирована политикой браузера). Рядом показать **локализованную небольшую инструкцию**, что файл надо переместить на рабочий стол и открыть двойным щелчком.
- При блокировке, предупреждении безопасности или невозможности загрузки — показать инструкцию Windows «ПКМ по рабочему столу → Создать → Ярлык → вставить URL калькулятора» и отдельную кнопку **«Скопировать адрес калькулятора»** внутри справки. Не обходить SmartScreen/антивирус и не требовать отключения защиты.
- Проверить расширение, корректный MIME/Content-Disposition насколько это возможно на статическом GitHub Pages и поведение Chrome, Edge, Firefox для Windows 10/11. Не выдавать скачанный в «Загрузки» файл за автоматически размещённый на рабочем столе.
- Альтернативный метод: браузер Chrome/Edge может предложить установку веб-приложения, но этот метод не подменяет явно заказанное действие скачивания `.url`.

## 5. iOS: добавить на экран «Домой», без фиктивного файла

**Действие:** «Скачать ярлык для iOS».

- iOS **не позволяет обычной веб-странице тихо установить ярлык на домашний экран** и не поддерживает `beforeinstallprompt`. Не скачивать профили .mobileconfig, .ipa или фиктивные .url/.webloc и не пытаться открывать Apple Shortcuts без реального поддерживаемого процесса.
- По нажатию **сразу открывать локализованную справку** с пошаговым процессом: открыть фактический URL калькулятора в поддерживаемом браузере, выбрать «Поделиться» → «На экран Домой» / «Добавить на экран Домой» (и «Открывать как веб-приложение», если предлагается) → подтвердить «Добавить». Уточнять шаги и названия по текущей версии iOS; на iOS 16.4+ возможность добавления может быть и в других браузерах, поэтому не писать ложное «строго только Safari для всех iOS».
- Если пользователь находится во встроенном браузере Telegram/Instagram и нужный пункт отсутствует, дать понятное действие «Открыть в Safari», **показать/скопировать URL** и затем повторить инструкцию. Не делать необъяснимую ссылку на скачивание.
- После создания значка пользователь нажимает на него и попадает в калькулятор. Требуется правильная иконка/manifest там, где поддерживается; до одобрения графики инструкция не должна вводить в заблуждение.
- Не объявлять установку успешной от одного открытия справки. Не закрывать её автоматически и не навязывать системные разрешения.

## 6. Android: браузерная установка или понятный fallback

**Действие:** «Скачать ярлык для Android».

- При наличии фактически полученного браузерного `beforeinstallprompt` запомнить событие; при **непосредственном клике пользователя** показать штатное окно установки `prompt()`. Никакой автоматической установки при входе на страницу или без жеста.
- Независимо от результата открывать доступ к локализованной справке: «Меню браузера → Установить приложение / Добавить на главный экран → Подтвердить». Если показан штатный prompt, справку можно открыть после закрытия/отклонения через явную ссылку «Как установить», чтобы не перекрывать системный диалог.
- Если событие установки недоступно (браузер, среда, уже установленное приложение, отключённые условия PWA, встроенный WebView), показывать **ручную инструкцию**, а не кнопку с пустым `onclick`. Не использовать неуниверсальные `intent://` или Play Store как обязательное решение.
- Обрабатывать результат `userChoice` и, если доступно, `appinstalled` без отслеживания личности. После подтверждённой установки можно заменить CTA на «Уже установлено» или «Открыть инструкцию» и не показывать повторный prompt. Если установка отклонена — не считать её завершённой, предложить ручной путь.
- Отдельно тестировать Android Chrome (PWA/shortcut), Samsung Internet (если доступно) и браузер без `beforeinstallprompt`; включить проверку поведения при открытии внутри Telegram/Instagram.

## 7. Web App Manifest и PWA только в рамках быстрого доступа

Для корректного имени и значка добавить **один** Web App Manifest, при необходимости минимальные совместимые метатеги, с явными параметрами:

- `name` — Nomad360 lite; `short_name` — Nomad360.
- `start_url` — **точный рабочий URL калькулятора** (пока внутри `/shelter-partner-directory/Marketing_calc.HTML`), а не корень github.io с другими продуктами.
- `id` — стабильный идентификатор именно этого веб-приложения, не объединять с SHELTER; проверить одно приложение на устройствах.
- `scope` — корректная область GitHub Pages, не шире всего hostname; если каталог проекта включает другие продукты, не регистрировать обработчик перехвата их страниц.
- `display` — `standalone` только если проверено, что все расчётные экраны, формы, файлы, ссылки, печать/PDF и полный HTML Embed работают в установленном режиме; иначе обосновать браузерный fallback.
- `icons` — реальные утверждённые файлы соответствующих размеров/типов. Нельзя выдумывать финальную иконку или ссылаться на отсутствующий файл.
- `lang`/`description` — проверенные общие метаданные; реальный выбор интерфейсного языка при запуске не ломать. Функции SEO-07 `?lang=...` и сохранённое предпочтение должны работать как согласовано.

**Service Worker / офлайн:** не включать в обязательный scope. **Не внедрять** без отдельного аудита: финансовые расчёты, сохранение черновиков, обновления, валюты/FX, внешние шрифты/скрипты и платежи могут вести себя некорректно при кэшировании. Даже если браузер может установить приложение без SW, не выдавать такой ярлык за полноценный офлайн-калькулятор. Если для install prompt требуется дополнительное условие в конкретном браузере — зафиксировать, предложить минимальное безопасное решение и проверить его отдельно; **запрещено кэшировать чужую корневую страницу SHELTER**.

**Будущий собственный домен:** исходные ярлыки на GitHub Pages должны вести на старый работающий URL; замена домена — отдельное SEO/redirect-решение, нельзя автоматически поменять установленный пользователем ярлык Windows. Не обещать бесшовную миграцию origin/storage.

## 8. Поведение модального окна/справки

- Единый доступный компонент справки под три платформы с локализованным заголовком «Как установить ярлык» и платформенными шагами. Для мобильных систем он открывается по нажатию соответствующей кнопки, кроме случая, когда поддерживается прямой системный prompt (Android).
- Никаких отвлекающих fullscreen-лендингов, регистрации, переадресации в магазин приложений, непроверенных QR и автоскачивания неизвестных файлов.
- Клавиатура: TAB, Enter/Space, фокус в окне, закрытие Escape и явной кнопкой, возврат фокуса к вызвавшей кнопке. Для `dialog` соблюдать aria-labelledby, aria-modal, отсутствие потери контента для скринридера.
- При смене RU/EN/KK во время открытой справки **сохранить платформу и шаг**, поменять только язык текста. При повторном открытии после re-render не дублировать обработчики.
- Кнопки доступны и на других ОС, но если нажата несоответствующая ОС — честно открыть инструкцию для выбранной системы, без принудительного редиректа. Определять платформу через UA можно лишь как вспомогательную подсказку, не для скрытия любой из трёх кнопок.
- Никаких HTTP-запросов, содержащих финансовые данные посетителя. Не добавлять отслеживание кликов, push-уведомления, подписки и скрытые метрики «ретеншна».

## 9. Границы изменений и совместимость

**Защищено от изменения**:
- Финансовая логика V1 для товаров/услуг и V2 для портфеля, модель налогов/кредита/Cash Flow, исходные данные и сохранённые расчёты.
- RU/EN/KK интерфейс и уже утверждённые тексты задачи 6; CTA, hero, «О проекте», лицензия, контакты, фиатные/криптоплатежи, тексты поддержки.
- Скачивание HTML Embed, его статусы подготовки и повторная ссылка; генерируемый независимый embed для сайтов консультантов **не должен получать новый промобаннер или URL-ярлыки на хосте заказчика по умолчанию**. Путь `Nomad360-lite.url` должен указывать на публичный оригинал и не зависеть от origin сайта покупателя/встроенного экземпляра.
- SEO-07: статический HTML трёх языков, canonical/hreflang, sitemap, исходные маршруты, query-параметры и страницы для консультантов. Баннер — **пользовательская часть живого калькулятора**, а не отдельная индексируемая SEO-страница.
- Репозиторный корневой `index.html`, относящийся к SHELTER Partner Directory.

**Порядок работы:** сначала макет текстового баннера и проверка места относительно «Поддержать проект», затем Windows-ярлык и справка, iOS-справка, Android-install flow, manifest и тесты; утверждённую графику добавить только после передачи дизайнерского файла владельцем. До её утверждения контент и логика могут быть приняты без картинки, но финальную визуальную приёмку баннера фиксировать отдельно.
