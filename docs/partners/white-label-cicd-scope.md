# WL-CICD-01 — White Label от €600: обновления разработчика и расширение функций без потери фирменного оформления

**Статус: продуктовая спецификация / NOT IMPLEMENTED (25.10.2026).** Новое обязательное качество **индивидуального коммерческого варианта** White Label, а не готовая функция нынешнего бесплатного HTML. Требование включить в будущую сравнительную таблицу EN/RU/KK во время R1 UI-подготовки, публично активировать с реальным обслуживаемым продуктом после R3–R6. Отдельная платная лицензия и договор имеют приоритет над рекламными формулировками.

## Что обещаем клиенту

**White Label — от €600 за индивидуально согласованный проект.** Вместе с клиентским брендом и SEO-адаптацией предлагаем **поддерживаемую версию калькулятора**: новые совместимые выпуски Nomad360 от разработчиков, исправления и согласованные новые возможности могут **автоматически доставляться** на инфраструктуру заказчика через настроенный CI/CD, **с сохранением его фирменных стилей** (логотипа, цветовой схемы, шрифтов, компонентов и разрешённых брендированных текстов).

**Значение слов и коммерческие границы:**
- «Автоматические обновления» = автоматизированная **сборка, тестирование и доставка** *одобренных и совместимых* upstream релизов в индивидуальную версию в рамках договора и подключённого pipeline. Не безусловное принудительное изменение сайта без согласия клиента; публикация может иметь approval gate и окно релиза.
- «Расширение функционала» = перенос доступных в новых версиях платформы функций и **возможность** заказать дополнительные специфичные функции с отдельной оценкой/сметой. Не обещать, что любые будущие разработки, bespoke CRM/SEO/налоговые сценарии или неограниченные доработки включены в €600.
- Цена **от €600** — стартовая стоимость индивидуальной адаптации/развёртывания в согласованном объёме, **не пожизненное обслуживание** и не безлимитные обновления. Отдельно указать в договоре срок и состав сопровождения, частоту выпусков, стоимость постоянного CI/CD/хостинга, работы по изменению интеграций и новых функций, поддержку и прекращение услуги.
- «Сохранение бренда» = визуальные и разрешённые текстовые изменения заказчика живут **отдельным слоем конфигурации**, не затираются при апстримных обновлениях. Новые UI-компоненты требуют автоматических снимков/проверок и, при необходимости, согласования адаптации; недопустимо обещать, что любое новое окно по умолчанию идеально стилизуется без проверки.
- «Автоматические» **возможно только для подключённой и управляемой поставки** с согласованным доступом к deploy (собственная площадка Nomad360, согласованный deploy worker, разрешённый PR/CI заказчика). Автономный HTML или вручную скачанный ZIP **не могут получать удалённые обновления автоматически** без дополнительной инфраструктуры; для клиента без доступа к CI/CD предложить ручной совместимый update package, но не позиционировать это как автоматическое обновление.

## Архитектурный контракт

1. **Upstream** — версионированный неизменяемый движок, формулы, налоговая логика, схемы черновиков, официальные release tags/manifest/SHA. Не допускать индивидуальной правки общего core калькулятора для внешнего брендирования.
2. **Tenant profile** (private) — отдельные `customer-id`, лицензия, разрешённые брендинговые параметры (logo asset, fonts, palette design tokens, CSS theme entrypoint, тексты контактной/SEO-страницы), locale EN/RU/KK и allowlisted integration configuration. Секреты, IP, токены и персональные заявки **не в Git/ZIP**.
3. **Customer theme overlay** — слои токенов/компонентов и версионированных ассетов с гарантированным порядком импорта поверх base style; не редактировать генерируемый `nomad360_palette.css` вручную. Запретить внедрение произвольного JS/CSS клиента в математический runtime без review. Иерархия default → customer theme → разрешённые исключения; contrast/mobile/accessibility smoke.
4. **Release pipeline** в приватном `lazysellerV2` или согласованном CI заказчика: upstream tagged release → сборка клиентского профиля → manifest/SHA/SBOM где применимо → unit/numeric oracles V1/V2/VAT/US Retail → браузерная EN/RU/KK и responsive 320–desktop матрица → snapshot diff тем/логотипов → совместимость localStorage/экспортов → preview/staging → approval gate → deploy по TLS в разрешённый origin → healthcheck → атомарный rollback. Ветка другого проекта (Lazyseller/Infourok/Product Factory) не должна запускать клиентские релизы.
5. **Защита индивидуализации**: неизменяемые profile snapshot и theme digest, baseline до и после обновления, визуальное сравнение; несовместимый UI компонент блокирует автоактивацию и создаёт задачу адаптации (не удаляет бренд или тексты), конфликт не маскировать.
6. **Control plane**: разделить аккаунт/ключи клиента и нашего производителя, принцип минимальных прав, секреты в менеджере секретов, audit trail версии и согласования, авторизованный rollback, запрет передачи финансовых черновиков разработчикам. Бот/интеграции/домен — отдельное разрешение заказчика. Данные и хранилище остаются у заказчика по договору.
7. **Платёжная/юридическая граница**: White Label требует отдельного письменного соглашения; действующая `CALCULATOR_LICENSE.md` §5 уже говорит, что €600 — ориентир и не включает неограниченное обслуживание. Не менять эту действующую лицензию в docs-only PR и не распространять платную лицензию на Free Embed.
8. **Доступность услуги**: если support contract истёк, pipeline/deploy не включён или клиент запретил изменения, отображать статус управляемого обновления корректно. Не гарантировать частоту, SLA, сроки, uptime, полный доступ к будущему core или бесконечное право на новые релизы без договора.

## Этапы и Definition of Done

- **R1**: согласовать русский/английский/казахский оффер, строку сравнения и реальные условия; внести будущий текст в preview без изменения текущих опубликованных обещаний.
- **R2**: SEO-редактура B2B страницы с честным термином `managed updates`, без обещаний ранжирования, CRM «из коробки» или незамеченных новых функций.
- **R3**: приватные profile schema, theme overlay, version manifest, pipeline per tenant и CI по scope; доказать что нет сквозного вмешательства в остальные продукты и финансовый движок.
- **R4**: клиентский staging/deploy adapter, доступ/логирование/откат, TLS/CDN/WAF по SEC-01, согласование домена и право на изменение сайта. Без доступа к клиентскому deploy не обещать автоматическую доставку.
- **R5**: независимые тесты core обновления с кастомной темой; новые компоненты, конфликт CSS, валюты/налоги, restore после миграции, отмена обновления, отключённый CI, сбой публикации, rollback и подтверждение принятия клиентом.
- **R6**: коммерческая лицензия/договор с чёткими обязательствами поддержки, бюджетом CI/CD, SLA если заказан, согласием на deploy, отозванием секретов, exit/ручным обновлением и условиями сохранения персонализированной версии. Только после выпуска включить реальную строку/оффер на сайте.

**Критерий завершения:** два последовательных контролируемых upstream релиза действительно доставлены до staging-домена тестового White Label клиента с сохранением брендового профиля и визуальными парами до/после, полным числовым parity, проверкой сохранений и доказанным rollback; отдельно согласованные коммерческие условия. Без этого — только будущая спецификация, а не «работает прямо сейчас».
