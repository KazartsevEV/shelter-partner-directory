# Nomad360: границы модулей

Исходная база этого среза — `main` после PR #218 (`b9802d0`). Цель — развивать
партнёрскую поставку без копирования формул в формы, хедер или сборщик архива.

| Слой | Текущий источник истины | Допустимая ответственность |
| --- | --- | --- |
| Финансовая модель V2 | `portfolio_v2_*engine.js`, чистые расчётные модули, налоговые и платёжные адаптеры | Числа, денежные потоки, распределение затрат |
| Финансовая модель V1 | Расчётные функции внутри `Marketing_calc.HTML` | Действующие формулы; переносить целиком только с независимым числовым оракулом |
| Бизнес-правила | Подготовка состояния V1/V2, `nomad360_payments.js`, `nomad360_fx.js`, `nomad360_price_export.js` | Валидация платежа, применение курса по явному действию, прайс из результата движка |
| Интерфейс | `nomad360_calculator_ui.js`, `portfolio_v2_ui.js`, `portfolio_v2_linked_ui.js`, `nomad360_header.js` | Ввод, навигация, вывод статусов и чисел; без собственного расчёта цен |
| Черновики | `nomad360_draft_store.js` | Именованные ключи, JSON, проверка формы старых данных, обработка запрета хранилища |
| Доставка | `nomad360_delivery.js` | Сборка автономного HTML из существующих локальных ресурсов; без черновиков и финансовых формул |

`Nomad360DraftStore` сохраняет исходные ключи `marketingCalcProductResultV1`,
`marketingCalcPortfolioV2`, `marketingCalcLinkedPortfolioV2` и прежний JSON без
миграции. `readV1`, `readPortfolio`, `readLinked` возвращают `null` для
неподходящего или недоступного черновика; `write*` и `removeV1` возвращают
результат операции. Интерфейс отвечает за пользовательское сообщение и за
синхронизацию платежей **до** записи. Хранилище не конвертирует валюты.

`Nomad360Delivery.buildStandalone(base)` возвращает готовый HTML. Сборщик
загружает каждый локальный ресурс один раз на выгрузку, встраивает CSS-фоны,
шрифты, JS и логотип, исключает исходный модуль ярлыков. Хедер управляет
кнопкой, статусом и скачиванием Blob. Сборщик не читает пользовательские
черновики и не отправляет их в сеть. Публичная кнопка остаётся прежней до
отдельного этапа партнёрской выдачи.

## Проверенные старые конструкции

- Дублирующий текст валюты создавался хедером и тут же удалялся баннером
  ирбиса. Удалён источник строки и послерендерная очистка. Селектор
  `.nomad-unit-note` больше не требуется в рабочем калькуляторе.
- Логотип B2B присутствует в шаблоне, но скрыт отдельным CSS. Его не удаляли:
  исходники автономной демонстрации ещё содержат этот узел, а визуальный
  контракт проверяет именно скрытое состояние.
- `nomad360_palette.css` — сгенерированный слой. Селекторы и цвета нельзя
  чистить вручную по одному текстовому совпадению: сначала нужен охват
  активных веток V1/V2/Help и регенерация из исходного генератора.

## Следующие безопасные границы

1. Вынести оставшиеся V1-функции ценообразования и Cash Flow из HTML в чистый
   движок с явным входным состоянием; перед переносом снять независимые
   числовые снимки own/resale/dropship/услуг, VAT/Sales Tax и кредита.
2. Привести изолированную US Retail демоверсию и налоговые надстройки к общему
   адаптеру черновиков после отдельной проверки их ключей и сценариев reset.
3. Для партнёров задавать бренд, контакты и разрешённые опции через
   версионированный конфиг сборки. Конфиг не должен содержать формулы или
   изменять движки; каждый пакет связывается с версией и контрольными суммами.
4. Форма заявки, проверка email, выдача персонального ZIP и фиксация домена
   относятся к следующему продуктовому этапу. Доступность публичного JS не
   может служить технической защитой от копирования.
