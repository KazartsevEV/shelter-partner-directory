# Nomad360: границы модулей

Исходная база этого среза — `main` после PR #218 (`b9802d0`). Цель — развивать
партнёрскую поставку без копирования формул в формы, хедер или сборщик архива.

| Слой | Текущий источник истины | Допустимая ответственность |
| --- | --- | --- |
| Финансовая модель V2 | `portfolio_v2_*engine.js`, чистые расчётные модули, налоговые и платёжные адаптеры | Числа, денежные потоки, распределение затрат |
| Финансовая модель V1 | `nomad360_v1_engine.js` | Ценообразование, кредит, Cash Flow товаров/услуг, помесячный онлайн-сценарий; явное входное состояние |
| Бизнес-правила | Подготовка состояния V1/V2, `nomad360_payments.js`, `nomad360_fx.js`, `nomad360_price_export.js` | Валидация платежа, применение курса по явному действию, прайс из результата движка |
| Интерфейс | `nomad360_calculator_ui.js`, `portfolio_v2_ui.js`, `portfolio_v2_linked_ui.js`, `nomad360_header.js` | Ввод, навигация, вывод статусов и чисел; без собственного расчёта цен |
| Черновики | `nomad360_draft_store.js` | Именованные ключи, JSON, проверка формы старых данных, обработка запрета хранилища |
| Доставка | `nomad360_delivery.js` | Сборка автономного HTML из существующих локальных ресурсов; без черновиков и финансовых формул |

`Nomad360DraftStore` сохраняет исходные ключи `marketingCalcProductResultV1`,
`marketingCalcPortfolioV2`, `marketingCalcLinkedPortfolioV2` и прежний JSON без
миграции. `readV1`, `readPortfolio`, `readLinked` возвращают `null` для
неподходящего или недоступного черновика; `write*` и `removeV1` возвращают
результат операции. Интерфейс отвечает за пользовательское сообщение и за
синхронизацию платежей **до** записи. Хранилище не конвертирует валюты.

`Nomad360Delivery.buildStandalone(base)` возвращает готовый HTML. Сборщик
загружает каждый локальный ресурс один раз на выгрузку, встраивает CSS-фоны,
шрифты, JS и логотип, исключает исходный модуль ярлыков. Хедер управляет
кнопкой, статусом и скачиванием Blob. Сборщик не читает пользовательские
черновики и не отправляет их в сеть. Публичная кнопка остаётся прежней до
отдельного этапа партнёрской выдачи.

## Проверенные старые конструкции

- Дублирующий текст валюты создавался хедером и тут же удалялся баннером
  ирбиса. Удалён источник строки и послерендерная очистка. Селектор
  `.nomad-unit-note` больше не требуется в рабочем калькуляторе.
- Логотип B2B присутствует в шаблоне, но скрыт отдельным CSS. Его не удаляли:
  исходники автономной демонстрации ещё содержат этот узел, а визуальный
  контракт проверяет именно скрытое состояние.
- `nomad360_palette.css` — сгенерированный слой. Селекторы и цвета нельзя
  чистить вручную по одному текстовому совпадению: сначала нужен охват
  активных веток V1/V2/Help и регенерация из исходного генератора.

## Выделение движка V1

База — принятый `main` после PR #238 (`c0a1e834`). Обе страницы
`Marketing_calc.HTML` и `US_Retail_Demo.HTML` используют один
`nomad360_v1_engine.js`; их прежние 18 расчётных функций совпадали побайтно.
Теперь HTML содержит совместимые делегаты и сбор входного состояния формы.

`Nomad360V1Engine.create(input)` принимает:

| Поле | Значение |
| --- | --- |
| `portfolio` | Прежние V1-снимки SKU с исходными платежами и применённой конвертацией |
| `businessTaxType` | Прежнее машинное значение налоговой модели |
| `businessTaxPct` | Ставка налога бизнеса |
| `salesVatChoice` | Прежний выбор `yes` / `no` / незавершённое значение |
| `salesVatPct` | Ставка VAT |

Результат экземпляра предоставляет прежние функции расчёта портфеля, цен,
кредита и Cash Flow. Pure helpers доступны также непосредственно из модуля.
`calculateSimpleService({values, mode, payers})` возвращает воронку,
помесячные числовые строки, итоги, P&L, Cash Flow и показатели онлайн-услуги.
`validateSimpleService` и `unassignedSimpleAgentExpenses` возвращают прежние
диагностики без обращения к DOM.

Движок не читает DOM, язык, валютные котировки или хранилище, не выполняет
сетевые запросы и не меняет входные объекты. UI сохраняет ответственность за
ввод, подготовку себестоимости из подробных полей, нормализацию платежей,
сохранение и отображение. Налоговые надстройки VAT/Sales Tax остаются на своих
прежних границах. Порядок округления и алгоритмы не изменены.

42 полных снимка товаров/услуг и 27 онлайн-сценариев сняты до переноса в
`tests/fixtures/v1-engine/accepted-main.json`. Перенесённые 18 тел функций
проверяются побайтно против принятого коммита; существующие независимые
оракулы теперь вызывают общий модуль напрямую.


## Хранилище US Retail и налоговых надстроек V1

База — принятый `main` после PR #239 (`d615271c`). В `US_Retail_Demo.HTML`
чтение, запись и удаление используют те же делегаты `Nomad360DraftStore`, что
и основная страница. Товарная и сервисная надстройки Sales Tax также делегируют
JSON-транспорт адаптеру. Формулы, налоговые состояния, обёртки сохранения и
порядок восстановления не меняются.

- `readV1()` проверяет портфель перед открытием формы, как и раньше.
- `readV1Raw()` нужен налоговым надстройкам: исторически они читали JSON до
  проверки портфеля. Частичная старая запись не становится допустимым
  портфелем и не удаляется при чтении.
- `readSimpleSalesTax()` / `writeSimpleSalesTax()` используют существующий
  независимый ключ `nomad360SalesTaxSimpleV1`. Ставка сохраняется исходной
  строкой; адаптер не преобразует её и не рассчитывает налог.
- Новый расчёт очищает текущее состояние формы, сохраняя прежний браузерный
  черновик. Удаление последнего сохранённого SKU удаляет только V1-портфель;
  выбор налога упрощённых услуг остаётся в своём ключе.
- Запрет доступа к хранилищу возвращает `null` при чтении и `false` при
  записи. Решение о сообщении пользователю остаётся у существующего UI.

В этом срезе не изменяются ключи V1/V2, формат сохранений, валютная
нормализация, поставка автономного HTML, готовые FILLED-демонстрации и
партнёрская выдача. Точный журнал замен и исходные контрольные суммы:
`tests/fixtures/tax-draft-storage/extraction.json`. Каждый hunk обратим
побайтно к принятой базе; посторонние изменения отклоняет source guard.

## Версионированная партнёрская сборка

Следующий срез после #240 — build-time контракт и сборщик
[`partner-package-config.md`](partner-package-config.md). Источник формул остаётся
в движках, сборка вызывает существующий `Nomad360Delivery.buildStandalone`.
Конфиг хранит только публичную идентичность пакета/партнёра, версию и профиль;
бренд/официальные контакты/полный набор возможностей v1 профиля неизменны.
Контрольные суммы связывают HTML, конфигурацию и все локальные ресурсы с Git SHA.

Это не работающая партнёрская выдача: форма, пароль ZIP, подтверждение email,
доставка и фактическое ограничение домена ещё впереди. Отдельные brand/contact
адаптеры White Label добавляются только с согласованным профилем; настройки
не должны менять финансовые функции или молча скрывать их интерфейсы.
