# TYPE-02 A — эталон закупки и сертификатов V2

Этап A предъявляет один реальный экран самостоятельного V2 в двух вариантах: исправленный IBM Plex Sans и Inter. Это материал для выбора гарнитуры и визуальной приёмки. Этап B, остальные формы, hero, About/Contacts и маркетинг ещё не реализованы. Merge не разрешён.

База: `main` `b1cc9b50ae48c3c8f392e4342fb5243c7575bd8e`, включая принятый PR #139 и исправление счётчика PR #141. Задача 5 закрыта; пользователь дал указание начать TYPE-02.

## Первопричина и каскад

1. `body` и `.nd-type-body` имеют вес 500. Общий `body > section .text-xs` задаёт 15 px и 500; `body > section :is(label,legend,.font-semibold)` повышает метки до 600. Вторичные пояснения оказываются близки по насыщенности к основному тексту.
2. `body > section :is(.text-xs,.text-sm)` применяет размер через `!important`, поэтому исходные `.text-xs`/`.text-sm` не задают разные роли.
3. Глобальный селектор `body > section :is(h2,h3,h4,.text-xl,.text-2xl):not(#nomad360-hero h2):not(#nomad360-hero h3)` содержит два ID в `:not()` и имеет чрезмерную специфичность. Он задаёт 700 даже при попытке назначить разделу роль 600.
4. Введённые значения получают общий 17 px / 500 через `!important`; placeholder наследует тот же вес. Заголовок карточки `strong` имеет 700, а заголовок раздела остаётся 18 px, поэтому карточка и раздел почти не отличаются.
5. Контроллер валидации записывает 12 px / 650 непосредственно в `style`. Это отдельный источник мелкого и нештатного по весу текста.

Для эталона пять конфликтующих глобальных правил исключают только потомков `.nd-type02-reference` через `:not(:where(...))`. `:where()` добавляет нулевую специфичность: селекторы и их приоритеты для остальных экранов сохраняются. Эталонные роли находятся рядом с существующими V2-компонентами в `nomad360_design_system.css`, а не новым глобальным слоем в конце файла.

Включение строго ограничено `#p2-stage-purchase.nd-type02-reference`. Рабочие HTML/JS-маршруты этот класс не добавляют. Его активирует только тестовый просмотр на реальной форме. После структурной перерисовки тест снова включает эталон; автоматическое включение в продукте относится к этапу B после приёмки. Семантических контейнеров существующего шаблона достаточно, поэтому JS-модули не изменялись.

Уведомление об ошибке получает лишь два локальных `!important`: 14 px и 500 против записанных контроллером inline-значений. Цвет, красная граница, `role=alert`, `aria-invalid`, текст и условие блокировки расчёта сохраняются. Новых глобальных `!important` нет.

## Реальные роли

Одна локальная шкала токенов управляет обоими вариантами; различается только гарнитура. Существующие классы `.nd-type-body`, `.nd-type-section`, `.nd-type-label`, `.nd-type-note`, `.nd-type-action`, `.nd-type-number` сохранены. Глобальная миграция этих ролей ещё не выполнялась.

| Роль, RU 390 px | До: px / weight | Оба кандидата: px / weight | Line-height после |
| --- | --- | --- | --- |
| Раздел | 18 / 700 | 23 / 600 | 28,98 px |
| Обычное описание | 16 / 500 | 17 / 400 | 26,35 px |
| Карточка | 17 / 700 | 19 / 600 | 25,46 px |
| Метка | 15 / 600 | 16 / 500 | 22,72 px |
| Введённое значение | 17 / 500 | 16 / 400 | 23,2 px |
| Select | 17 / 500 | 16 / 400 | native `normal` |
| Подпись checkbox | 15 / 600 | 16 / 500 | 22,72 px |
| Вторичное пояснение | 15 / 500 | 14 / 400 | 21 px |
| Действие | 17 / 600 | 16 / 600 | 21,6 px |
| Placeholder | 17 / 500 | 16 / 400 | native |
| Ошибка | 12 / 650 | 14 / 500 | существующие 1,4 |

Размер раздела адаптивен: 23–26 px. Описание ограничено 75ch, сохранён полный текст без ellipsis или max-lines. Денежные input используют `tabular-nums`; минимальный размер input/select — 16 px, активные зоны — не менее 44 px. Палитра, рамки, сетки и порядок полей сохранены.

## Шрифты

Восемь неизменённых WOFF2-файлов из Google Fonts занимают 307 788 байт: Cyrillic Extended, Cyrillic, Latin Extended и Latin для каждой семьи. Оригинальные SIL OFL-файлы включены в `vendor/fonts/type02/`; основная лицензия приложения не менялась. Источники, SHA-256, оси variable fonts и cmap-аудит FontTools записаны в manifest.

IBM Plex Sans объявляется теми же дискретными 400/500/600/700, что и действующий Google import. Inter использует 400–700 variable face. Подключение для эталона централизовано в отдельном review-only `fonts.css`, с `font-display:swap`; этот файл не добавлен в рабочие страницы. Дополнительных `@import` и новых сетевых запросов продукта нет. Решение о едином рабочем подключении принимается после выбора шрифта.

Chromium CDP `CSS.getPlatformFontsForNode` проверяет **Ә ә Ғ ғ Қ қ Ң ң Ө ө Ұ ұ Ү ү Һ һ І і** во всех четырёх весах. Для каждого знака браузер использует ожидаемую custom font family, без подстановки системной семьи. Оба варианта имеют все требуемые казахские глифы; Inter не получает преимущество за счёт fallback.

## Проверки

- 72 контрольных снимка: 3 языка × 4 ширины (320/390/768/1280) × 3 варианта (до/Plex/Inter) × 2 состояния (заполнено/ошибка охвата). Модель, строки сохранённого черновика, финансовый результат и ошибки совпадают с архивом точной базы.
- 12 проверок без активированного эталона подтверждают неизменные computed styles реального экрана. Для кандидатов все проверенные роли вне секции закупки совпадают с базой.
- 6 сценариев редактирования суммы до 125000 KZT, перехода на распределение по загрузке, динамических полей и восстановления после reload. Сумма, валюта, распределение и результат сохраняются.
- 6 проверок 200% desktop reflow: 1280 физических px / 640 CSS px / DPR 2. Это автоматическая проверка эквивалентной геометрии и media queries; ручное переключение браузерного zoom остаётся частью визуальной приёмки.
- 12 сценариев с заблокированными внешними запросами и всеми WOFF2: системный fallback сохраняет поля, суммы и отсутствие переполнений на 320/1280 px.
- Минимальный измеренный контраст в секции **7,29:1**. Нет переполнения страницы, выходящих за экран элементов, обрезанных числовых input, потерянных ошибок или изменения расчётных чисел.
- 225 финансовых/связанных unit-регрессий успешно; ещё 2 проверки неизменности защищённых исходников и оригинальных font assets успешно. CSS разобран PostCSS, новый JavaScript прошёл syntax check, workflow YAML проверен.

CI checkout `6e6c93b8` и PR-head имеют одинаковое дерево `a0a1189f`. ZIP артефакта `11910774272` скачан и проверен по SHA-256; все 84 PNG и протокол опубликованы из этого ZIP без изменения. Последующая синхронизация guard/census и публикация доказательств не меняют код/CSS эталона. CI запускает отдельный `TYPE-02 A typography reference` на точном финальном PR-head. Фактический статус и SHA финального запуска фиксируются в описании PR и живой Issue #119. Зелёный CI подтверждает проверки этапа A; он не объявляет завершённым весь TYPE-02.

## Обнаруженное прежнее ограничение

В исходном `main` при снятии подтверждения охвата сертификата текст «Подтвердите область действия, страну и срок сертификата «certification» для всех товаров.» остаётся русским в EN и KK. Это воспроизводится в архиве базы **до CSS-изменений**, отмечается `auditVisibleGaps` и присутствует в исходном PNG. Оба кандидата сохраняют ровно тот же gap; тест не скрывает сообщение и не считает эту строку переведённой. Дефект зарегистрирован как отдельный долг локализации; исправление текста/enum запрещено областью TYPE-02 и в этот PR не включено.

Отдельный online-import набор здесь не выполнялся; 13 ранее зарегистрированных падений не пересмотрены. Успех CSS-проверок не снимает эти ограничения и не подменяет полную языковую приёмку.
