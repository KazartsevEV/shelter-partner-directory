Каждый `strings` ID связан с записью в [RU](texts-ru.json), [EN](texts-en.json) или [KK](texts-kk.json): реальный текст, тип атрибута и DOM-контекст. Список поверхностей находится в summary; исходные шаги и тестовые данные — в `tests/nomad360_localization_l0_browser.cjs`.

[findings.json](findings.json) группирует исходные сигналы `auditVisibleGaps` по владельцу и контексту. В 96 состояниях есть сигналы; 42 содержат точное совпадение с известным KK-словарём, 60 содержат сигнал для разбора (категории могут пересекаться). Это не число дефектов: диагностический исходник может быть усечён до 240 символов, содержать пользовательское название или корректный казахский заголовок с номером. `rawTextObservedCases` отмечает точное совпадение исходного сигнала с фактическим видимым текстом. `userNameOnly` выделяет название демо, которое переводить нельзя.

Не объявляется полная языковая/лингвистическая приёмка, не изменяются исходные строки и текущий шоппер. Протокол создаёт проверяемую очередь для L1–L6. [Отчёт L0](../localization-l0-review.md) · [исходный реестр](../../localization/l0/README.md).
