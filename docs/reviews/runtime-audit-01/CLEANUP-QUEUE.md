# Очередь очистки после приёмки baseline

Это **кандидаты**, не выполненные исправления. Принятие аудита не разрешает
объединять их в один большой рефакторинг. Полные адреса правил, offsets и условия:
[generated index](INDEX.md), [полный AST/CSS census](runtime-inventory.json.gz).

| Порядок | Отдельный срез | Условия перед удалением/изменением |
| --- | --- | --- |
| C1 | Два одинаковых правила `body #full-service-screen .nd-full-service-inputs` в `nomad360_design_system.css` | Проверить промежуточные каскадные правила, CSSOM-зависимости, полный/упрощённый сервис и оба V2. Если удаление подтверждено — убрать более ранний дубль, регенерировать палитру штатным генератором, сохранить порядок слоёв и сравнить computed styles/снимки/числа |
| C2 | Дубли `.nomad-seo-logo-mask` в мобильном `nomad360_calculator_ui.css` | Не менять логотип/кроп/геометрию. Проверить header, 320–768/desktop, три языка, скачанный HTML и старые source guards; при споре сохранить |
| C3 | Два набора повторных About-правил в `nomad360_about_banner.css` | Не менять принятый фон/цвет/композицию. Условия `max-width:700px` и `min-width:1001px` проверять раздельно, включая края breakpoint; использовать принятые эскизы и pixel/computed-style сравнение |
| C4 | Семь повторных групп в **генерируемом** `nomad360_palette.css` | Исправлять причину в `scripts/palette/build.cjs`, а не вручную в output. Не менять первую декларацию/порядок layer и приоритет `!important`. Проверить все источники дубликатов и запрет альтернативных цветов/шрифтов |
| C5 | Остальные переопределения: 224 группы с разными значениями | Не считать их дубликатами: часть намеренно перекрывает старую тему. Для каждого отдельного компонента определить владельца/область, только затем заменять общим классом с тем же computed style |
| C6 | Оставшаяся связанность бизнес-операций и UI в HTML | Отдельно от CSS: `calculate`, `updateCalculatedMaterialsCost`, `recalculateMaterialsLandedCost`, `recalculateProductAdFunnel` и подготовка состояния. Сохранить движки/округления/налоги/порядок вызовов и совместимые глобальные адаптеры; не переносить сразу всю форму |
| C7 | Исторические/сгенерированные копии и неиспользованные в матрице селекторы | Старые FILLED HTML, архивные `.github/workflows/*.html` и чужой SHELTER `index.html` не являются автоматически мёртвым кодом. Проверить ссылки, CI/фикстуры, прямые опубликованные URL и старые разрешённые копии; сохранять до отдельного решения |

Для C1–C4 статическая идентичность подтверждается AST, но одного этого недостаточно
для смены source guards или удаления каскадных блоков. Не удалять позднее правило
только потому, что раннее выглядит таким же: позднее могло восстанавливать значение
после промежуточных overrides. Не удалять обёртку `@layer`, если она задаёт порядок.

## Защищённые группы

- 171 динамическое обращение к селекторам, конструируемые IDs/classes,
  делегированные события, inline HTML handlers и строки печатных/экспортных шаблонов.
- 2 677 селекторов без DOM-совпадения в измеренной матрице: это **не** перечень
  разрешённых удалений. Ещё 64 селектора не поддержаны этим DOM probe, включая
  псевдоэлементы и ключевые кадры; их отсутствие не равно отсутствию CSS-эффекта.
- Глобальные делегаты V1 и два независимых HTML entrypoint. Имя с малым числом
  обычных JS-вызовов может вызываться inline-атрибутом или поздним адаптером.
- Встроенные Inter WOFF2 и обязательные атрибуции: размер CSS сам по себе не
  доказывает лишний код. Библиотека ExcelJS — отдельный third-party ресурс.

## Производительность и будущий hosting

В пяти повторных переходах home → V2 число `JSEventListeners` оставалось **304**
во всех 18 комбинациях. Это доказательство для конкретного пути, не отсутствие
любых утечек. Сравнивать после очистки тем же сценарием; V8 heap может колебаться
даже после GC и не отражает всю память браузера.

Начальная загрузка в лабораторном прогоне составила 6,20–8,49 MB без HTTP-сжатия.
Крупные ресурсы: About SVG около 2,39 MB, оригинальный PNG-логотип около 1,50 MB,
ExcelJS около 0,95 MB. Это отдельная очередь оптимизации доставки: без перерисовки
баннеров/логотипа, потери утверждённых цветов и нарушения автономного экспорта.
Никакой графики в аудите не меняли.

В production HTML остаётся неприкреплённый к версии Tailwind CDN. Аудит, как и
действующие регрессионные тесты, использует локальный pinned Tailwind 3.4.17.
Самостоятельная поставка CSS/зависимостей, HTTP-сжатие, кэш и asset budget должны
войти в подготовку hosting отдельным PR, с проверкой динамических классов и
автономного HTML. Лабораторные timings не выдавать за скорость текущего CDN.

## Приёмка каждого cleanup PR

1. Узкий diff, описание владельца компонента и доказательство удаляемой зависимости.
2. Сохранённый исходный baseline и прежние числовые оракулы; не подгонять их под код.
3. RU/EN/KK, 320/360/390/430/768/desktop, скрытые ветки, оба V2/услуги/агент,
   восстановление, PDF/Excel и свежий автономный HTML.
4. До/после: bytes/gzip/Brotli, число обработчиков и DOM, paired timing runs на
   одинаковой среде. Для timings повторить одинаковую комбинацию хотя бы трижды;
   не принимать ухудшение без объяснения. Не вводить произвольный жёсткий SLA
   по единственному текущему измерению.
5. Пользовательская приёмка и отдельное разрешение на merge до следующего среза.
