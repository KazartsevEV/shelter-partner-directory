## Смысл, который нельзя изменить при редактуре

- Калькулятор проверяет финансовые последствия **пользовательских предположений**, но не спрос, конверсию реальных продаж или прибыльность без внешних проверок.
- Один товар/услуга — V1; портфель с индивидуальными и общими расходами — V2. Расчёты бизнеса и цены не равны банковским прогнозам.
- Маржа **не равна** наценке; прибыль **не равна** Cash Flow и Available Cash. В SEO-текстах нет выдуманного SLA, абсолютной автономности или обещания рыночной доходности.
- B2B-клиенты размещают инструмент на собственном сайте и обрабатывают обращения **своими средствами**: Nomad360 не собирает лиды и не пересылает расчёты посетителей партнёрам.
- Бесплатный HTML сохраняет текущие атрибуцию, юридические условия и необходимость самостоятельной установки. Не обещать ни автоматическое обновление ZIP, ни уже работающую новую партнёрскую выдачу. White Label от €600, managed updates через согласованный CI/CD и его коммерческие границы оформлены **отдельным будущим контрактом**, не как готовая функция Free версии.
- SEO-ядро: [EN/RU/KK semantic core](../semantic-core-ru-en-kk.md). KK — **редакционные кандидаты**, не результат носительской лингвистической приёмки и не доказанные частотные ключи. EN → RU → KK с сверкой профессиональных терминов по [глоссарию](../../localization/nomad360-terminology.md).

## Что проверено в подготовительном пакете

Для всех 10 редакций проведена сравнительная структурная проверка относительно `scripts/seo/pages.json`: **10/10 совпадений** идентификаторов исходника, тематики, числа разделов, абзацев, карточек, табличных строк, обратных ссылок `related` и внутренних карточных ссылок; **0 ошибок**. Проверены проектные адреса `ru/` / `kk/`, локализованные `?lang=ru|kk` с сохранением CTA-якоря, допустимый статус непубликации. Title/meta-описания подготовлены отдельно и укорочены до практичных редакционных длин; Google не гарантирует отображение текста целиком.

Это **проверка полноты и формы**, не браузерная приёмка и не носительская языковая экспертиза. Реальный рендер отсутствует: исходный генератор `scripts/seo/build.py` намеренно ограничен `locale == 'en'` и содержит английские навигацию, тексты подвала и `hreflang=en`, которые нужно локализовать при подключении. Нельзя просто скопировать существующий английский HTML и заменить body.

## Следующий отдельно проверяемый технический срез

1. Сверить и принять EN/RU редактуру; переводы KK — **отдельная живая языковая приёмка**, поправить кальки и терминологию.
2. Адаптировать `scripts/seo/build.py` / данные страниц для трёх локалей **одним генератором** (не ручное копирование 10 HTML): навигация, `lang`, `og:locale`, skip link, подвал, атрибуция и ссылки каждой локали.
3. Встроить тексты без изменения `Marketing_calc.HTML`, `index.html` чужого SHELTER, финансовой логики, браузерных черновиков, скачать автономный HTML.
4. Настроить **только реальные reciprocal** `hreflang`, `x-default` при согласовании, self-canonical для реально отданного HTML и `sitemap.xml` по доказанным URL. `robots.txt` внутри project path не управляет корнем `github.io`.
5. Доказать файловый HTML, HTTP 200, source/DOM, кликабельность CTA к `?lang=ru`/`?lang=kk`, корректный якорь, отсутствие 404 и языковых конфликтов, реальный `lang` браузера, мобильный 320/360/390/430/768/1280.
6. Включить полный существующий CI SEO/финансов/браузерного storage/экспортов; обновить screenshots/baselines только при фактическом изменении рендера и после явного review.
7. Отдельный PR, пользовательская приёмка, решение о публикации; исходный PR с контентом **не публикует** десять страниц и не меняет production.
